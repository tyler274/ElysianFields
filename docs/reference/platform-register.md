## Governance & Decision Alignment

- **Decision D2 (Target failure policy):** If a target fails M1 qualification, attempt a narrow gatekeeper-approved adapter first (e.g., native OS text/IME overlay, AccessKit/ARIA bridge, or lightweight HTML popup for the Chrome extension). If no narrow adapter fits, drop the non-core target with explicit owner sign-off. **Hard stop:** If **Browser Wasm accessibility** or **Browser Wasm text input** fails without a narrow adapter, stop the entire program for review.
- **Decision D4 (Required desktop targets):** Linux, macOS, and Windows are all required targets despite zero current shipped desktop evidence in `01b762838`. Every desktop target therefore starts from `none` reference support and must produce full M1 feasibility evidence (text/IME, AccessKit screen readers, graphics backend, build/link time) on real hardware before M2.
- **No-disappearance rule:** Unavailable physical hardware (e.g., macOS/iOS, Windows, physical Android ARM64) is recorded as `blocked-no-hardware`, never waived or treated as a pass.
- **Subpath deployment constraint:** All Elysian Fields browser Wasm bundles and APIs must operate cleanly under `https://dabney.moe/elysianfields/` (not assuming domain root `/`).
